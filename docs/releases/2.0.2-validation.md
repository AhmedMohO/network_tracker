# NetTrack 2.0.2 release validation

Version: 2.0.2, version code 16. Package: `com.anonymous.network_tracker`.

## Completed checks

- `:app:testDebugUnitTest :app:lintRelease :app:assembleRelease --no-daemon --offline`: passed, including R8 release packaging; 115 JVM tests passed and release lint reported zero errors. Existing warnings remain.
- `--init-script scripts/validation.init.gradle :app:connectedDebugAndroidTest --offline`: all 22 tests passed with zero skips on a Samsung SM-A356E running Android 17. This includes real Android usage totals, legacy archive migration/rollback, Wi-Fi sessions, a live Wi-Fi callback without dashboard polling, disabled tracking, permission recovery, English/Arabic themes, family navigation, Wi-Fi limit selection and background scheduling.
- Two older UI assertions were updated to the current permission recovery action and family setup tab. Failures were reproduced before correcting those assertions.
- `scripts/test-signing-rotation.ps1`: disposable app upgraded with the old/new signing lineage, retained its app-private marker and signature permission, and rejected a higher-version old-key update.
- Archive migration checks: 2 passed. Family device-removal SQL fixture: 1 passed.
- Existing family client key validated through actual read-only `family_pull` RPC calls with newly generated, empty pairing tokens. The root schema endpoint's 401 was not a valid diagnosis of the client key. The original client key is retained. Supabase confirms the device-removal function and its anonymous EXECUTE privilege are already installed; no server data or schema was changed.
- Final static release review found no concrete release-blocking issue. The public release notes omit the section excluded by the user.

## Release artifacts

`NetTrack-v2.0.2.apk`: 2,657,846 bytes, V3 rotation for Android 9+ in-place updates. SHA-256: `ae147c40657b2b513ba8ad8960779af4db38703529646ca1364619c4c395a4d9`.

`NetTrack-v2.0.2-fresh-install-android7.zip`: 2,338,958 bytes, contains the separately signed Android 7+ fresh-install APK and installation guidance. SHA-256: `23ef05656b66b3b59f9b6d82e6404967e49bb18257f2aa31fa1a2c6129a2ed37`.

Both APKs report version code 16 / version 2.0.2. Both use new certificate SHA-256 `b4249e84f6603fcf83eb965f1c2ce6ff12139700b0fc3bb059bd51e4a30aed3c`. The main APK is verified with minimum signing API 28; the fresh-install APK is verified with minimum API 24. The primary APK retains the application's API-24 manifest but its V3-only signature requires Android 9+.

Only one `.apk` is published as a direct release asset, so existing updaters select the rotation-capable package. The Android 7+ fresh-install APK is deliberately distributed inside the ZIP. Checksums accompany both assets. Private keys and signing passwords are excluded from Git and release assets. An encrypted, round-trip-verified Windows DPAPI backup was saved outside the repository.

## Device scope

Testing used disposable validation packages; the installed production 2.0.1 app and its data were not overwritten or cleared. Android 9–16 physical signing migration and overnight Doze/reboot behavior were not exercised. Existing Android 7/8 old-key installations have no secure in-place certificate-rotation path and must not be uninstalled or cleared as a workaround.
